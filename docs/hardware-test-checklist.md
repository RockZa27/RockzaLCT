# คู่มือทดสอบกับฮาร์ดแวร์จริง (RockzaLCT)

เอกสารนี้สำหรับเจ้าของเครื่อง ที่มี MCTRL300 / MCTRL660 / MCTRL700 และ VX400 / VX600 / VX1000 / VX2000 Pro (ต่อได้ทั้ง USB และ LAN)

**เหตุผลที่ต้องทดสอบ:** โค้ดถูกเขียนจากไลบรารี `@novastar/*` และทดสอบกับการ์ดจำลองเท่านั้น ยังไม่เคยคุยกับเครื่องจริง มีหลายค่าที่ "เดา" จากเอกสารไลบรารี (ระบุว่า UNVERIFIED ในโค้ด) งานของคุณคือบอกเราว่าค่าไหนถูก ค่าไหนผิด

เรียงลำดับจากปลอดภัยที่สุดไปเสี่ยงที่สุด **ทำทีละขั้น อย่ากระโดดข้าม และหยุดทันทีที่เจออะไรผิดปกติ**

---

## 0. ความปลอดภัย (อ่านก่อนเสมอ)

1. ทดสอบกับ **จอเล็กหรือชุดทดสอบ** ก่อน อย่าลองครั้งแรกกับจอที่ติดตั้งใช้งานจริงหรือจอที่ลูกค้ารออยู่
2. ขั้นที่ 1–10 เป็น **อ่านค่า/สั่งชั่วคราว** (ความสว่าง ภาพทดสอบ จอดำ/หยุดภาพ ไม่ต้องล็อกอินขั้นสูง และค่าจะหายเมื่อปิดไฟ) ขั้นที่ 11 เป็นต้นไป **เขียนค่าที่ต้องล็อกอินขั้นสูง** และขั้นที่ 12 **เขียนลงแฟลชถาวร**
3. **สำรองค่าก่อนเขียนทุกครั้ง:** เมนู **บันทึก/โหลด** → ส่วน **อ่านค่ากลับและบันทึกเป็นไฟล์** → กด **อ่านจากตัวควบคุม** → กด **บันทึกไฟล์ตั้งค่า…** เก็บไฟล์ `.json` ไว้หลายชุด (ตั้งชื่อตามรุ่นและวันที่) และถ่ายรูป/จดค่าของ NovaLCT เดิมที่ใช้งานอยู่ไว้ด้วย
4. ถ้าอ่านแล้วขึ้น "อ่านส่วนเหล่านี้ไม่สำเร็จ" หรือ "ข้อมูลที่อ่านได้ไม่ครบ" ไฟล์สำรองนั้น **ไม่สมบูรณ์** อย่าถือว่าเป็น backup
5. การเขียนต้อง **เข้าสู่ระบบขั้นสูง** (ปุ่ม **เข้าสู่ระบบขั้นสูง** มุมบน) รหัสผ่านเริ่มต้นของโปรแกรมคือ `admin` (โหมด `--mock` ใช้ `rockza`) ยังไม่ต้องล็อกอินจนกว่าจะถึงขั้นที่ 11
6. ห้ามถอดสาย USB/LAN หรือปิดไฟระหว่างที่โปรแกรมกำลัง "บันทึกลงฮาร์ดแวร์"
7. ถ้ามีตัวควบคุมหลายตัวในเครือข่ายเดียวกัน ให้ถอดตัวอื่นออกก่อน เพื่อไม่ให้เขียนผิดเครื่อง
8. ถ้าจอผิดปกติหลังการทดสอบ: ปิดไฟตัวควบคุมแล้วเปิดใหม่ (ค่าที่ยังไม่บันทึกลงแฟลชจะกลับเป็นค่าเดิม) หรือโหลดไฟล์ที่สำรองไว้ผ่านเมนู **บันทึก/โหลด** → **เปิดไฟล์ตั้งค่าและนำไปใช้**

---

## วิธีบันทึกผล

ทุกขั้นมีช่อง "ถ้าต่างจากที่คาด ให้จด" ให้จดลงตารางผลท้ายเอกสาร (หัวข้อ 14) พร้อมถ่ายภาพหน้าจอโปรแกรมและภาพจอ LED ถ้าเกี่ยวกับการแสดงผล แล้วส่งกลับมา

ข้อมูลที่ต้องแนบทุกครั้ง: รุ่นตัวควบคุม, รุ่นการ์ดรับ (ป้ายบนการ์ด), ช่องทางเชื่อมต่อ (USB/LAN), เวอร์ชันโปรแกรม (`RockzaLCT-Setup-x.y.z.exe`)

---

## 1. ติดตั้งโปรแกรม

1. ดาวน์โหลด `RockzaLCT-Setup-<เวอร์ชัน>.exe` (จากหน้า Releases หรือ Actions → Artifacts ของ GitHub)
2. Windows SmartScreen อาจเตือน "unknown publisher" เพราะไม่ได้เซ็นดิจิทัล เลือก **More info → Run anyway**
3. ติดตั้งแล้วเปิดโปรแกรม **RockzaLCT**

**คาดว่า:** หน้าต่างภาษาไทยเปิดขึ้น เมนูซ้าย: การเชื่อมต่อ, ความสว่าง, ทดสอบและการแสดงผล, การ์ดส่ง, การ์ดรับ, ผังการเชื่อมต่อจอ, บันทึก/โหลด, ตรวจสอบสถานะ แถบบนแสดง **ยังไม่ได้เชื่อมต่อ**

**ลองโหมดจำลองก่อน (ไม่ต้องมีฮาร์ดแวร์):** สร้างทางลัดของโปรแกรมแล้วเติม ` --sim` ท้ายช่อง Target (เช่น `"C:\Users\<ชื่อ>\AppData\Local\Programs\RockzaLCT\RockzaLCT.exe" --sim`) หรือรันจาก PowerShell แล้วกดค้นหา ควรเจอตัวควบคุมจำลอง ถ้าใช้ได้แสดงว่าตัวติดตั้งสมบูรณ์ **การเปิดแบบปกติ (ไม่มี `--sim`) คือโหมดต่อเครื่องจริง**

**ถ้าเปิดไม่ขึ้น/ขึ้น error เกี่ยวกับ serialport:** จดข้อความทั้งหมด ถ่ายภาพ และหยุดทดสอบ (เป็นปัญหาของตัวติดตั้ง)

---

## 2. เชื่อมต่อทาง USB

1. ต่อสาย USB จากตัวควบคุมเข้าคอมพิวเตอร์ เปิดไฟตัวควบคุม รอให้ Windows ติดตั้งไดรเวอร์ (ดูใน Device Manager ว่ามี COM port ใหม่ — **จดหมายเลข COM**)
2. ปิด NovaLCT เดิมและโปรแกรมอื่นที่ใช้พอร์ต COM นั้นอยู่ (ใช้พร้อมกันไม่ได้)
3. เมนู **การเชื่อมต่อ** → กด **ค้นหา**
4. ในตาราง **ตัวควบคุมที่พบ** หาแถวประเภท **อนุกรม (USB/COM)** → กด **เชื่อมต่อ**

**คาดว่า:** พบตัวควบคุม แถบบนเปลี่ยนเป็น **เชื่อมต่อแล้ว: <ชื่อ>** มีกล่อง **ตัวควบคุมที่เชื่อมต่ออยู่**

**จดถ้าต่าง:** ไม่พบเลย / พบแต่เชื่อมไม่ได้ / ข้อความ error (เช่น `ตัวควบคุมไม่ตอบสนองภายในเวลาที่กำหนด`, `การสื่อสารกับตัวควบคุมผิดพลาด`) / มีหลาย COM แล้วเลือกผิด / ค้างนานเท่าไร

กด **ตัดการเชื่อมต่อ** ก่อนทดสอบช่องทางถัดไป

---

## 3. เชื่อมต่อทาง LAN

1. ต่อสาย LAN จากตัวควบคุม (หรือผ่านสวิตช์) เข้าเครือข่ายเดียวกับคอมพิวเตอร์ ตั้ง IP คอมพิวเตอร์ให้อยู่วงเดียวกับตัวควบคุม (ตรวจ IP ของตัวควบคุมจากเครื่องมือเดิม/คู่มือ) พอร์ตเริ่มต้นของโปรแกรมคือ 5200
2. เมนู **การเชื่อมต่อ** ช่อง **โฮสต์เครือข่าย (ไม่บังคับ คั่นด้วยเครื่องหมายจุลภาค)** ใส่เช่น `192.168.0.10` หรือ `192.168.0.10:5200` (ใส่หลายเครื่องคั่นด้วย `,`)
3. กด **ค้นหา** → แถวประเภท **เครือข่าย (LAN)** → **เชื่อมต่อ**
4. Windows Firewall อาจถามสิทธิ์ ให้อนุญาตบนเครือข่ายส่วนตัว

**จดถ้าต่าง:** ไม่พบ / ใช้พอร์ตอื่นที่ไม่ใช่ 5200 หรือไม่ / เชื่อมสำเร็จแต่ข้อมูลต่างจาก USB หรือไม่ / อ่านค่าช้ากว่า USB มากหรือไม่

---

## 4. อ่านข้อมูลอุปกรณ์ (อ่านอย่างเดียว)

เมนู **การเชื่อมต่อ** → กล่อง **ตัวควบคุมที่เชื่อมต่ออยู่** ดูช่อง **รุ่น**, **เฟิร์มแวร์**, **พอร์ตเอาต์พุต**, **การ์ดรับ** (ตารางคอลัมน์ พอร์ต / การ์ดที่ / รุ่น / เฟิร์มแวร์)

**คาดว่า:**
- **รุ่น** จะแสดงเป็น `Unknown (0x....)` เพราะไลบรารีไม่มีตารางชื่อรุ่น — **นี่คือสิ่งที่ต้องการ: จดเลข 0x.... ให้ตรงกับรุ่นจริงที่เป็นเจ้าของ** (เช่น MCTRL660 → 0x????) ทุกเครื่อง เราจะใช้ทำตารางชื่อรุ่น
- **เฟิร์มแวร์** รูปแบบ `a.b.c` (หรือ `a.b.c.d`) เทียบกับเวอร์ชันใน NovaLCT เดิมว่าตรงกันหรือไม่
- **พอร์ตเอาต์พุต** ตรงกับจำนวนพอร์ตจริงของรุ่น (ตรวจตามคู่มือเครื่องของรุ่นนั้น)
- **การ์ดรับ** จำนวนตรงกับที่ต่ออยู่จริงหรือไม่ ถ้าไม่ตรงให้จดพอร์ตที่ขาด/เกิน

**จดถ้าต่าง:** model id (0x....) ของแต่ละรุ่น, เฟิร์มแวร์ที่ไม่ตรงกับ NovaLCT, จำนวนพอร์ต/การ์ดที่ผิด

---

## 5. ความสว่าง (เขียนชั่วคราว ความเสี่ยงต่ำ)

เมนู **ความสว่าง**: ตัวเลื่อน **ความสว่างรวม**, **เกนสีแดง / เขียว / น้ำเงิน**, ปุ่ม **นำไปใช้**, กล่อง **ค่าที่อ่านกลับจากอุปกรณ์**

1. ดูค่าที่อ่านกลับก่อน จดไว้เป็นค่าเดิม
2. ปรับ **ความสว่างรวม** ลงเล็กน้อย (เช่น −10) กด **นำไปใช้** → ต้องเห็นข้อความ **ปรับความสว่างแล้ว** และจอมืดลงจริง
3. ลองปรับเกนทีละสี ดูว่าสีบนจอเปลี่ยนตรงสี (แดงเปลี่ยนแดง ฯลฯ)
4. **คืนค่าเดิม** แล้วกด **นำไปใช้**

> หมายเหตุ: ความสว่างไม่ต้องล็อกอินขั้นสูง ค่าที่ตั้งเป็นค่าชั่วคราวและหายเมื่อปิดไฟ (ถ้าโปรแกรมแจ้ง `ไม่มีสิทธิ์ ต้องเข้าสู่ระบบขั้นสูงก่อน` ให้จดไว้ด้วย)

**จดถ้าต่าง:** ค่าอ่านกลับไม่ตรงกับที่ตั้ง (บอกค่าที่ตั้งและค่าที่อ่านกลับ), จอไม่เปลี่ยน, สีสลับกัน, สเกลของตัวเลขต่างจาก NovaLCT (เช่น 100% ของ NovaLCT เท่ากับค่าอะไรในโปรแกรม)

## 6. ภาพทดสอบ (Test Patterns)

เมนู **ทดสอบและการแสดงผล** → ส่วน **ภาพทดสอบ**: **ปิด, แดง, เขียว, น้ำเงิน, ขาว, เส้นแนวนอน, เส้นแนวตั้ง, เส้นทแยง, เกรย์สเกล**

กดทีละปุ่ม ดูที่จอ LED แล้วจบด้วย **ปิด** เสมอ

**คาดว่า:** จอแสดงสี/ลายตามชื่อ และ **ปิด** กลับสู่ภาพปกติ

**จดถ้าต่าง:** ปุ่มไหนแสดงผิดสี/ผิดลาย (เช่น กด "เส้นแนวนอน" แต่ได้เส้นแนวตั้ง), ปุ่มไหนไม่มีผล, **ปิด** แล้วภาพไม่กลับ (ถ้าไม่กลับให้ปิด-เปิดไฟตัวควบคุม)

## 7. จอดำ / หยุดภาพ (ค่า byte ยังไม่ยืนยัน)

เมนู **ทดสอบและการแสดงผล** → ส่วน **โหมดการแสดงผล**: **ปกติ, จอดำ, หยุดภาพ**

ทดสอบ **ขณะมีวิดีโอเคลื่อนไหวเข้ามาที่ตัวควบคุม** (เช่น เปิดวิดีโอหรือเลื่อนหน้าต่างในจอคอมที่ส่งภาพมา) เพื่อให้เห็นความต่างของ "หยุดภาพ"

1. กด **จอดำ** → จอควรดับ (ภาพดำ) กด **ปกติ** → ภาพกลับ
2. กด **หยุดภาพ** → ภาพบนจอควรค้างทั้งที่ต้นทางยังเคลื่อนไหว กด **ปกติ** → กลับมาเคลื่อนไหว
3. ลองสลับ จอดำ → หยุดภาพ → ปกติ ต่อเนื่อง เพื่อดูว่าทั้งสองโหมดไม่ค้างติดกัน

ค่าที่โปรแกรมเขียนตอนนี้ (`DISPLAY_MODE_VALUES` ใน `packages/device/src/service.ts`):

| ค่า | ใช้ทำอะไร | ค่าปัจจุบัน |
|---|---|---|
| `killOn` | เปิดจอดำ (SetKillMode, รีจิสเตอร์ 0x02000100) | 1 |
| `killOff` | ปิดจอดำ | 0 |
| `lockOn` | เปิดหยุดภาพ (SetLockMode, รีจิสเตอร์ 0x02000102) | 1 |
| `lockOff` | ปิดหยุดภาพ | 0 |

**จดถ้าต่าง (สำคัญมาก):** จอดำทำงานหรือไม่ / หยุดภาพทำงานหรือไม่ / ทำงานแต่กลับเป็น "ปกติ" ไม่ได้ / จอดำแต่ได้ผลของหยุดภาพแทน (สลับกัน) / ผลเกิดกับการ์ดรับทุกใบหรือเฉพาะบางพอร์ต ถ้าหยุดภาพไม่ทำงาน ผู้พัฒนาสงสัยว่า `lockOn = 2` (ตาม ControlModeType: Normal=0, Black=1, Lock=2) ให้จดผลของค่าปัจจุบัน (1) ไว้ก่อน แล้วลองเปลี่ยนเองได้ตามบรรทัดด้านล่าง

> **แก้ค่าได้ทันที:** ถ้าจอดำหรือหยุดภาพไม่ทำงาน เข้าเมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง** (ต้องเข้าสู่ระบบขั้นสูงก่อน) แก้ `killOn / killOff / lockOn / lockOff` (เช่น `lockOn` เป็น 2) กด **บันทึกค่า…** แล้วกลับมาทดสอบขั้นนี้ซ้ำได้ทันที ไม่ต้องเชื่อมต่อใหม่และไม่ต้องรอผู้พัฒนา จดค่าที่ใช้ได้ลงตารางสรุปในขั้น 14

> ถ้าทดสอบแล้วจอค้างในโหมดจอดำ/หยุดภาพ และกด **ปกติ** ไม่หาย ให้ปิด-เปิดไฟตัวควบคุม

## 8. การ์ดส่ง (อ่านอย่างเดียวในขั้นนี้)

เมนู **การ์ดส่ง** (กด **รีเฟรช** เพื่ออ่านใหม่) ส่วน **สัญญาณขาเข้า** (**สัญญาณขาเข้า**: พบสัญญาณ / ไม่มีสัญญาณ, **ความกว้าง/ความสูง (พิกเซล)**, **อัตรารีเฟรช (ค่าดิบจากรีจิสเตอร์)**, **อัตราสัญญาณที่วัดได้ (ค่าดิบจากรีจิสเตอร์)**, **แหล่งสัญญาณ**), ส่วน **พอร์ตเอาต์พุตอีเทอร์เน็ต** (คอลัมน์ พอร์ต / เปิดใช้งาน / พื้นที่ที่โหลด / จำนวนพิกเซล / การ์ดรับ), ส่วน **สำรอง / รีดันแดนซี**

ขั้นนี้ **ห้ามกด นำไปใช้ใด ๆ** ให้ดูอย่างเดียว

**คาดว่า:** ความละเอียดตรงกับสัญญาณที่ป้อน (เช่น 1920×1080), สถานะสัญญาณถูกต้องเมื่อถอด/เสียบสายวิดีโอ, แหล่งสัญญาณตรงกับช่องที่เสียบจริง (ถ้าขึ้น "ไม่ทราบ (ค่าดิบ …)" ให้จดค่าดิบ), จำนวนพิกเซลต่อพอร์ตสมเหตุสมผล

**จดถ้าต่าง:** ความละเอียด/แหล่งสัญญาณผิด, ค่าดิบของอัตรารีเฟรชทั้งสองช่อง พร้อมอัตราจริง (เช่น 60 Hz → ค่าดิบ = ?) เพื่อใช้หาสูตรแปลงหน่วย, พอร์ตที่มีการ์ดแต่ไม่แสดง

## 9. การ์ดรับ (อ่านอย่างเดียว) และตรวจสอบสถานะ

### 9.1 การ์ดรับ

เมนู **การ์ดรับ** → เลือกจากรายการ **การ์ดรับ** (รูปแบบ "พอร์ต N / การ์ดที่ M (รุ่น)") → กล่อง **พารามิเตอร์ที่อ่านจากการ์ด** กด **อ่านใหม่** เพื่ออ่านซ้ำ

ดู: **ขนาดโมดูล (พิกเซล)**, **โหมดสแกน**, **กลุ่มข้อมูล (จริง / ตรรกะ)**, **กลุ่มข้อมูลต่อโมดูล**, **จำนวนแถวของโมดูล**, **ไอซีไดรเวอร์ (รหัส)**, **ตัวถอดรหัสแถว (รหัส)**, **จำนวนการรีเฟรชต่อเฟรม**, **ความลึกเกรย์สเกล (ค่าดิบ)**, **วิธีสร้างเกรย์สเกล**, **แกมมา (ค่าดิบจากรีจิสเตอร์)**, **อุณหภูมิ (ค่าดิบ)**, **แรงดันไฟ (ค่าดิบ)**

เปรียบเทียบกับค่าใน NovaLCT เดิม (เปิดดูได้ แต่อย่าให้ NovaLCT และ RockzaLCT เชื่อมพร้อมกัน) หรือกับสเปกโมดูล LED ที่ใช้

**จดถ้าต่าง:** ค่าที่ไม่ตรงกับ NovaLCT/สเปกโมดูล (ระบุชื่อช่อง, ค่าที่โปรแกรมแสดง, ค่าที่ถูก), ช่องที่ขึ้น **ไม่มีข้อมูล**, ขนาดโมดูล **กว้าง/สูงสลับกัน** หรือไม่, **ค่าแกมมาดิบ** เทียบกับแกมมาที่ตั้งใน NovaLCT (เช่น 2.8 → ดิบ = ?)

### 9.2 ตรวจสอบสถานะ (monitoring)

เมนู **ตรวจสอบสถานะ** (อ่านอย่างเดียว) เลือก **ช่วงเวลารีเฟรช** เช่น 5 วินาที หรือกด **รีเฟรชทันที** ดูสรุป **ออนไลน์ / ออฟไลน์ / คำเตือน / วิกฤต**, ตาราง **การ์ดรับ** ("พอร์ต N · การ์ด M", **อุณหภูมิ (ดิบ)**), **รายละเอียดการ์ด** (**อุณหภูมิ**, **ความชื้น**, **แรงดัน**, **บล็อกบิตผิดพลาด**, **การ์ดมอนิเตอร์ที่ต่อพ่วง**, **เตือนควัน**, **พัดลม**), ส่วน **การ์ดส่ง** (ลิงก์ ปกติ/บางส่วน/ขาด/ว่าง)

**ทดสอบเพิ่ม (ไม่ทำลายอะไร):** ถอดสาย Cat5 ระหว่างการ์ดรับหนึ่งใบแล้วรีเฟรช → การ์ดนั้นและใบถัดไปในสายควรเป็น **ออฟไลน์** / ลิงก์พอร์ตเป็น **บางส่วน/ขาด** แล้วเสียบกลับ → กลับเป็นปกติ

**จดถ้าต่าง:**
- **อุณหภูมิ (ดิบ) เทียบกับอุณหภูมิจริง:** เทียบกับค่าที่ NovaLCT แสดงในเวลาเดียวกัน จดคู่ (ค่าดิบ ↔ °C) อย่างน้อย 3 จุด (เช่นตอนเครื่องเย็น/อุ่น) และดูว่าค่าเป็น 0 หรือ 255 เสมอหรือไม่ (ลำดับ byte [valid, value] ของบล็อกอุณหภูมิ **ยังไม่ยืนยัน**)
- ความชื้น/แรงดันดิบ เทียบกับ NovaLCT
- การ์ดที่ออนไลน์อยู่แต่โปรแกรมบอกออฟไลน์ (หรือกลับกัน)
- สถานะพัดลม/ควัน ที่แสดงเตือนทั้งที่ปกติ

## 10. ผังการเชื่อมต่อจอ — อ่านจากฮาร์ดแวร์ (อ่านอย่างเดียว)

เมนู **ผังการเชื่อมต่อจอ** → ส่วน **ตัวควบคุม** กด **อ่านจากฮาร์ดแวร์** (ห้ามกด **ส่งลงฮาร์ดแวร์**)

**คาดว่า:** ข้อความ **อ่านผังจากตัวควบคุมแล้ว** และผังที่แสดงตรงกับการเดินสายจริง (ตู้แถว/คอลัมน์ไหนอยู่พอร์ตไหน ลำดับตู้) ถ้าตัวควบคุมไม่เคยตั้งผัง จะขึ้น **ตัวควบคุมยังไม่มีผังที่ตั้งค่าไว้**

กด **แสดงหมายเลขตู้บนจอ** เพื่อให้จอจริงโชว์หมายเลขตู้ (เทียบกับผังบนหน้าจอ) แล้วกด **ซ่อนหมายเลขตู้**

**จดถ้าต่าง (สำคัญ):**
- **ตำแหน่ง X/Y สลับกันหรือไม่:** ไลบรารีขัดแย้งกันเองเรื่องตำแหน่งการ์ด โค้ดตอนนี้ถือว่า byte 0–1 = Y และ byte 2–3 = X (`decodeScannerXY` ใน `packages/device/src/features/layout.ts`) ถ้าจอที่จัดเป็นสี่เหลี่ยมผืนผ้า (เช่น 4 คอลัมน์ × 2 แถว) แล้วผังที่อ่านออกมาเป็น 2 คอลัมน์ × 4 แถว หรือตู้ถูกสะท้อน/หมุน แสดงว่า X/Y สลับ — ถ่ายภาพผังบนโปรแกรมและภาพจอจริงที่แสดงหมายเลขตู้
- ข้อความ **การ์ดบนตัวควบคุมไม่เรียงเป็นตารางปกติ**, **การ์ดรับ N ใบยังไม่ได้ตั้งขนาด จึงข้ามไป** (จดค่า N)
- ลำดับหมายเลขตู้/ทิศทางเดินสาย ไม่ตรงกับของจริง

> **แก้ค่าได้ทันที:** ถ้าผังที่อ่านออกมา X/Y สลับกัน (ดูหัวข้อ **ตำแหน่ง X/Y สลับกันหรือไม่** ด้านบน) เข้าเมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง** (ต้องเข้าสู่ระบบขั้นสูงก่อน) เปลี่ยน **ลำดับ X/Y ของการ์ดรับ (scannerXyOrder)** เป็น **X อยู่ 16 บิตล่าง** กด **บันทึกค่า…** แล้วกลับมากด **อ่านจากฮาร์ดแวร์** ซ้ำได้ทันที ค่านี้ใช้ทั้งตอนอ่านและตอนเขียนผัง (ขั้น 13) เหมือนกัน

อย่าเพิ่งไปขั้นถัดไปถ้ายังไม่ได้ **สำรองค่า** ตามหัวข้อ 0 ข้อ 3

## ขั้นขั้นสูง (เสี่ยง: เขียนค่า) — ทำเมื่อผ่านขั้นก่อนหน้าและสำรองค่าแล้วเท่านั้น

> ทำบน **จอเล็ก/ชุดทดสอบ** และใช้ **การ์ดรับเพียงใบเดียว** ล็อกอินขั้นสูง (ปุ่ม **เข้าสู่ระบบขั้นสูง**, รหัส `admin`) แล้วแถบบนต้องขึ้น **ระดับ: ขั้นสูง**

## 11. เขียนค่าการ์ดรับ (การ์ดใบเดียว)

เมนู **การ์ดรับ** → เลือกการ์ดใบทดสอบ 1 ใบ **ตรวจให้แน่ใจว่าไม่ได้ติ๊ก "ใช้กับการ์ดรับทุกใบ (broadcast)"** → ส่วน **แก้ไขรีเฟรช แกมมา และเกรย์สเกล**

1. จดค่าเดิมของ **จำนวนการรีเฟรชต่อเฟรม**, **แกมมา**, **ความลึกเกรย์สเกล**, **วิธีสร้างเกรย์สเกล**, **โหมดเกรย์สเกล**
2. เปลี่ยนค่า **ทีละช่อง และเปลี่ยนน้อย ๆ** (เช่น แกมมาขยับเล็กน้อย) กด **นำไปใช้** → ต้องเห็น **ตั้งค่าการ์ดรับแล้ว**
3. กด **อ่านใหม่** ดูว่าค่าที่อ่านกลับตรงกับที่ตั้ง และดูจอว่าภาพเปลี่ยนจริงเฉพาะบริเวณของการ์ดใบนั้น
4. **คืนค่าเดิมทันที** กด **นำไปใช้**

**ห้ามใช้ "ไลบรารีโมดูล → ใช้กับการ์ด" ในขั้นนี้** เพราะเขียนทั้งขนาดโมดูล/สแกน/ไอซีหลายค่าพร้อมกัน ยกเว้นต้องการทดสอบแยกต่างหากบนการ์ดทดสอบที่ยอมให้เสียได้

**จดถ้าต่าง:** ค่าอ่านกลับต่างจากที่ตั้ง, ภาพเพี้ยน/กะพริบ/ดับ (ระบุค่าที่ตั้ง), เปลี่ยนแล้วกระทบการ์ดใบอื่น, หน่วยของแกมมาดิบเทียบกับ NovaLCT

## 12. บันทึกลงฮาร์ดแวร์ (ถาวร) + ทดสอบปิด-เปิดไฟ

เสี่ยงสุดของฝั่งการ์ดรับ เพราะเขียนแฟลช และ **ค่าคำสั่งบันทึกยังไม่ยืนยันกับเครื่องจริง** (`SAVE_COMMAND_VALUES` ใน `packages/device/src/features/persist.ts`: `sender = 1`, `receiver = 1`)

1. (ต้องมีไฟล์สำรองแล้ว) ทำขั้นที่ 11 ให้ค่าบนการ์ดทดสอบเปลี่ยนเป็นค่าที่ "ปลอดภัยและเห็นผลได้" เช่น แกมมาเปลี่ยนเล็กน้อย
2. เมนู **บันทึก/โหลด** → ส่วน **บันทึกลงฮาร์ดแวร์** → **บันทึกการ์ดใบไหน** เลือก **พอร์ต N / การ์ด M** ของการ์ดทดสอบ (**ไม่เลือก "การ์ดรับทุกใบ"**) และ **ไม่ติ๊ก "บันทึกการ์ดส่งด้วย"**
3. กด **บันทึกลงฮาร์ดแวร์…** → ยืนยันที่หน้าต่าง **บันทึกลงฮาร์ดแวร์?** ด้วย **ใช่ ดำเนินการต่อ** → ต้องเห็น **บันทึกการ์ดรับแล้ว 1 ใบ**
4. **ปิดไฟตัวควบคุม+จอ รอ 10 วินาที เปิดใหม่** เชื่อมต่อใหม่ แล้วเข้า **การ์ดรับ** → **อ่านใหม่**

**คาดว่า:** ค่าที่ตั้งยังอยู่หลังเปิดไฟใหม่ = บันทึกสำเร็จ (ค่า 1 ถูกต้อง) ถ้าค่ากลับไปเป็นค่าเดิม = คำสั่งบันทึกไม่ทำงานด้วยค่า 1

**จดถ้าต่าง:** โปรแกรมบอกสำเร็จแต่ค่าหายหลังปิดไฟ, error ระหว่างบันทึก (ข้อความ **บันทึกบางรายการไม่สำเร็จ**), จอผิดปกติหลังบันทึก

> **แก้ค่าได้ทันที:** ถ้าค่าหายหลังปิดไฟ เข้าเมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง** (ต้องเข้าสู่ระบบขั้นสูงก่อน) แก้ **ค่า byte บันทึกการ์ดรับ (saveReceiver)** หรือ **ค่า byte บันทึกการ์ดส่ง (saveSender)** กด **บันทึกค่า…** แล้วทำข้อ 2–4 ซ้ำได้ทันทีโดยไม่ต้องเชื่อมต่อใหม่ (ลองทีละค่า จดค่าที่ลองและผลลงตารางขั้น 14)
จากนั้น **คืนค่าเดิม แล้วบันทึกซ้ำให้ฮาร์ดแวร์กลับสู่สภาพเดิม** หรือโหลดไฟล์สำรอง (หัวข้อ 0 ข้อ 8)

ส่วน **การ์ดส่ง** (ติ๊ก **บันทึกการ์ดส่งด้วย**) ให้ทดสอบแยกเป็นรอบสุดท้าย และต้องเป็นค่าที่ไม่ได้เปลี่ยนแปลง (บันทึกค่าปัจจุบันซ้ำ) เท่านั้น

## 13. เขียนผังจอ บนจอเล็ก

ทำเมื่อขั้น 10 อ่านผังได้ตรงและมีไฟล์สำรองแล้ว **ใช้จอเล็กที่เดินสายง่าย (เช่น 2×2 ตู้)**

1. เมนู **ผังการเชื่อมต่อจอ** → **อ่านจากฮาร์ดแวร์** เพื่อเริ่มจากผังจริง
2. สร้างผังที่ **เหมือนของเดิมทุกประการ** ก่อน แล้วดูหัวข้อ **การตรวจสอบ** ต้องขึ้น **ผังถูกต้อง** กด **ส่งลงฮาร์ดแวร์** → ยืนยันในหน้าต่าง **ส่งผังลงตัวควบคุมหรือไม่** → **ส่งผัง** ต้องเห็น **ส่งผังแล้ว: N พอร์ต, M การ์ดรับ** และจอไม่เปลี่ยนจากเดิม
3. กด **อ่านจากฮาร์ดแวร์** อีกครั้ง ผังต้องเหมือนที่ส่ง
4. (ถ้ายังปลอดภัย) เปลี่ยนเล็กน้อย เช่น สลับรูปแบบเดินสาย (**รูปแบบการเดินสาย**) ส่งอีกครั้ง ตรวจด้วย **แสดงหมายเลขตู้บนจอ** ว่าตัวเลขบนจอจริงตรงกับผัง
5. ถ้าผิดพลาด: โหลดไฟล์สำรอง (**บันทึก/โหลด** → **เปิดไฟล์ตั้งค่าและนำไปใช้** → **เปรียบเทียบกับตัวควบคุม** → เลือก **ผังจอ** ใน **เขียนส่วนเหล่านี้** → **ใช้กับตัวควบคุม…**) หรือปิด-เปิดไฟ (ค่าที่ไม่ได้บันทึกแฟลชจะกลับมา)

**จดถ้าต่าง:** จอแสดงผิดตำแหน่งหลังส่ง, ผังที่อ่านกลับไม่ตรงกับที่ส่ง, **X/Y สลับ** (ดูขั้น 10), ข้อความ error ระหว่างส่ง, จอดับหลังส่ง

> **แก้ค่าได้ทันที:** ถ้า X/Y สลับ เข้าเมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง** (ต้องเข้าสู่ระบบขั้นสูงก่อน) เปลี่ยน **ลำดับ X/Y ของการ์ดรับ (scannerXyOrder)** กด **บันทึกค่า…** แล้วส่งผังซ้ำและอ่านกลับ (ข้อ 2–3) ได้ทันที โปรแกรมใช้ลำดับเดียวกันทั้งตอนอ่านและตอนเขียน จึงอ่านกลับได้ตรงกับที่ส่งเสมอ ให้ดูที่จอจริง (แสดงหมายเลขตู้) ว่าตรงกับผังหรือไม่ ไม่ใช่ดูแค่ที่อ่านกลับ

## 15. H5 / H series (ผ่าน LAN, UDP 6000)

ส่วนนี้สำหรับเจ้าของ **H5** (และ H2 / H9 / H15 / H20 ถ้ามี) เป็นอุปกรณ์คนละตระกูลกับ MCTRL/VX: คุยด้วยข้อความ JSON ผ่าน **UDP พอร์ต 6000** ไม่ใช่โปรโตคอลไบนารี TCP 5200 และไม่มีทาง USB/COM ในโปรแกรมนี้

**เหตุผลที่ต้องทดสอบ:** โค้ดฝั่ง H series เขียนจากการอ่านพฤติกรรมของโมดูล Companion โอเพนซอร์ส (`kman1898/companion-module-novastar-splicer` v3.0.7 ซึ่งทดสอบกับ H5) ไม่ได้อ่านเอกสารโปรโตคอลทางการ (ติด NDA) และทดสอบกับตัวจำลองเท่านั้น ค่าใดที่ระบุ UNVERIFIED ในโค้ด (`packages/device/src/hseries/`) คือเดา งานของคุณคือบอกว่าถูกหรือผิด

ทำตามหัวข้อ 0 (ความปลอดภัย) เหมือนเดิม และ **ทำทีละขั้น หยุดทันทีที่เจออะไรผิดปกติ** ใช้ H5 ที่ไม่ได้ขึ้นจอใช้งานจริงของลูกค้า

### 15.1 เตรียมเครือข่าย

1. ต่อ H5 เข้าเครือข่ายเดียวกับคอมพิวเตอร์ (สาย LAN) แล้วดู **IP ของ H5** จากหน้าจอ/เมนูของเครื่องหรือจาก NovaLCT/เว็บของเครื่อง (**จด IP**) คอมพิวเตอร์ต้องอยู่ซับเน็ตเดียวกัน
2. ปิด NovaLCT / โปรแกรมควบคุม H5 อื่น ๆ ที่เปิดอยู่ (กันชนกันเอง)
3. Windows Firewall อาจถามสิทธิ์ครั้งแรกที่โปรแกรมส่ง UDP เลือก **อนุญาต** (ต้องรับ UDP ตอบกลับได้) ถ้าไม่ได้ผล ลองปิด firewall ชั่วคราวเพื่อแยกสาเหตุ แล้ว **จดว่าเป็นสาเหตุหรือไม่**

### 15.2 เชื่อมต่อ

1. เมนู **การเชื่อมต่อ** → ช่อง **โฮสต์เครือข่าย (ไม่บังคับ คั่นด้วยเครื่องหมายจุลภาค)** พิมพ์ IP ของ H5 (เช่น `192.168.1.50`) → กด **ค้นหา**
2. ในตาราง **ตัวควบคุมที่พบ** หาแถว `192.168.1.50:6000 (H series)` ประเภท **H series (UDP)** → กด **เชื่อมต่อ**
   - ถ้าใช้พอร์ตอื่นที่ไม่ใช่ 6000 ให้พิมพ์ `IP:พอร์ต` (พอร์ตที่ไม่ใช่ 5200 จะถูกใช้เป็นพอร์ต UDP ของ H series)
   - โปรแกรมจะถาม `R0118` ซ้ำจนเครื่องรายงานว่าพร้อม (rate 100) ถ้าเครื่องเพิ่งเปิดอาจรอได้ถึง 10 วินาที

**คาดว่า:** แถบบนเปลี่ยนเป็น **เชื่อมต่อแล้ว: H series** กล่อง **ตัวควบคุมที่เชื่อมต่ออยู่** แสดงรุ่น `H series` (โปรโตคอลที่โค้ดใช้ไม่มีฟิลด์ชื่อรุ่น/เฟิร์มแวร์ จึงขึ้น `unknown`), **พอร์ตเอาต์พุต** = จำนวนช่องของการ์ดส่ง (cardType 3) และไม่มีรายการการ์ดรับ เมนูซ้ายเหลือ: **การเชื่อมต่อ, ความสว่าง, ทดสอบและการแสดงผล, H series** (เมนูการ์ดส่ง/การ์ดรับ/ผังจอ/บันทึก-โหลด/ตรวจสอบสถานะ หายไป เพราะใช้กับ MCTRL/VX เท่านั้น)

**จดถ้าต่าง:** ไม่พบเลย (ลองเปิด NovaLCT ดูว่าเครื่องตอบ UDP 6000 ไหม; จด IP/พอร์ต/ข้อความ error เช่น `ตัวควบคุมไม่ตอบสนองภายในเวลาที่กำหนด`), พบแต่ค้างที่ "กำลังเชื่อมต่อ" (มีรายงานว่า H9 เคยค้างแบบนี้), จำนวนพอร์ตเอาต์พุตไม่ตรงกับการ์ดส่งที่ติดตั้งจริง, ชื่อรุ่นว่างหรือแปลก

### 15.3 อ่านค่า (ไม่ต้องล็อกอินขั้นสูง)

1. เมนู **H series** รอให้ตารางโหลด
2. เทียบกับหน้าจอ/เว็บของเครื่อง: รายชื่อ **หน้าจอ** (ชื่อ, ความสว่าง %, หยุดภาพ, ดับภาพ), **พรีเซ็ต** ของแต่ละหน้าจอ, **เลเยอร์** และรายการ **อินพุต** (อินพุตที่ไม่มีสัญญาณ/ออฟไลน์จะไม่แสดงในรายการเลือก)
3. เมนู **ความสว่าง** ค่าที่โหลดมาต้องเท่ากับความสว่างของ **หน้าจอแรก**

**คาดว่า:** ชื่อและจำนวนตรงกับเครื่อง ค่าความสว่างเป็น 0–100 เท่ากับที่เครื่องแสดง (ไม่มีการแปลงสเกล)

**จดถ้าต่าง:** รายการว่างทั้งที่เครื่องมี (จดว่ารายการไหน), ชื่อเพี้ยน/ภาษาไทยเป็นอักขระแปลก, **ความสว่างไม่ตรงกับเครื่อง**, สถานะหยุดภาพ/ดับภาพกลับด้าน (โปรโตคอล FTB กลับค่า: `Ftb.enable = 0` คือดับภาพ), จำนวนอินพุตขาดหรือเกิน, ถ้ามี crop ของอินพุตให้ดูว่าแสดง "(ครอป N)" ถูกที่

### 15.4 ความสว่าง (เขียนชั่วคราว ไม่ต้องล็อกอิน เหมือน MCTRL)

1. ยังไม่ต้องล็อกอิน (การ **บันทึก** ความสว่างถาวรในขั้น 15.8 เท่านั้นที่ต้องล็อกอินขั้นสูง)
2. เมนู **ความสว่าง** มีแถบเดียว (ความสว่างรวม) ไม่มีเกนสี RGB เพราะโปรโตคอล H series ไม่มี (ค้นแล้ว) ตั้งค่า เช่น 50 → **นำไปใช้**
3. ดูที่เครื่องจริง/เว็บของเครื่อง และกลับมาดูที่หน้า **ค่าที่อ่านกลับจากอุปกรณ์**
4. ตั้ง 100 ก่อนเลิกทดสอบ ค่าที่ตั้งนี้ **ยังไม่ถูกบันทึกลงการ์ดรับ** (ดูขั้น 15.8)

**คาดว่า:** ทุกหน้าจอของ H5 เปลี่ยนความสว่างเป็นค่าที่ตั้ง (โปรแกรมส่ง `W0410` ไปทุกหน้าจอ) ค่าที่อ่านกลับ = ค่าที่ตั้ง

**จดถ้าต่าง:** ปรับแล้วจอไม่เปลี่ยน, เปลี่ยนเฉพาะบางหน้าจอ, ค่าอ่านกลับต่างจากที่ตั้ง (จดทั้งสองค่า), มีข้อความ **ไม่มีสิทธิ์** ทั้งที่ล็อกอินแล้ว, เส้นความสว่างของ LED ที่เห็นจริงไม่เป็นเชิงเส้นกับตัวเลข

### 15.5 ภาพทดสอบ และ จอดำ / หยุดภาพ (ต้องล็อกอินขั้นสูง)

ภาพทดสอบส่งไปยัง **ทุกช่องเอาต์พุตของการ์ดส่ง** (`W0303` ต่อช่อง) โปรแกรมเลือกช่องจาก `R0300` กรองด้วยรายการช่องจริงของ `R0100`

1. เมนู **ทดสอบและการแสดงผล** กดทีละปุ่ม: **แดง, เขียว, น้ำเงิน, ขาว, เส้นแนวนอน, เส้นแนวตั้ง, เส้นทแยง, เกรย์สเกล** แล้วกลับมา **ปิด** ทุกครั้ง
2. **โหมดการแสดงผล:** **จอดำ** (`W0700` blackout ทั้งระบบ) → **ปกติ**; **หยุดภาพ** (`W040A` ทุกหน้าจอ) → **ปกติ**

**คาดว่า:** สีตรงกับที่กด ทุกช่องของการ์ดส่งแสดงลายเดียวกัน กด **ปิด** แล้วกลับเป็นภาพปกติ; จอดำ = ทุกหน้าจอดำ; หยุดภาพ = ภาพนิ่ง (ขยับต้นทางแล้วจอไม่ตาม) และ **ปกติ** ปลดทั้งสองอย่าง

**จดถ้าต่าง:** 
- **เส้นทแยง** ในโปรแกรมใช้ "Lines: Diagonal Right" (0x0203) และ **เกรย์สเกล** ใช้ "Gradient: White (Horizontal)" (0x0103) ซึ่งเป็นการเลือกลายที่ใกล้เคียงที่สุด (**UNVERIFIED**) — จดว่าลายที่ขึ้นเป็นอะไรจริง และทางทแยงเป็น `/` หรือ `\`
- ปุ่ม **ปิด** ไม่ทำให้ลายหาย (ต้องกลับเป็น 0xFFFF), ลายขึ้นเฉพาะบางช่อง/ช่องนอกการ์ดส่ง, ความสว่าง/ระยะ/ความเร็วของลาย (ค่าที่โปรแกรมส่ง: bright 3, grid 5, speed 3) ผิดปกติ
- จอดำ/หยุดภาพ: ทำงานไหม, สลับจากจอดำไปหยุดภาพโดยตรงได้ไหม, หลัง **ปกติ** ยังมีหน้าจอใดค้างอยู่ไหม

### 15.6 พรีเซ็ต (ต้องล็อกอินขั้นสูง ผลเห็นบนจอทันที)

1. เมนู **H series** → ส่วน **พรีเซ็ต** เลือกพรีเซ็ตที่ **ปลอดภัย** (เช่น ที่รู้ว่าเป็นภาพเริ่มต้น) → กด
2. ดูที่เครื่อง/จอว่าพรีเซ็ตถูกเรียกบนหน้าจอที่เลือก

**คาดว่า:** เห็นข้อความ **เล่นพรีเซ็ตแล้ว: <ชื่อ>** และเครื่องโหลดพรีเซ็ต (`W0605`) บนหน้าจอนั้นเท่านั้น

**จดถ้าต่าง:** โหลดผิดหน้าจอ/ผิดพรีเซ็ต (ID ไม่ตรงกับเลขบนเครื่อง?), ไม่เกิดอะไร, error

### 15.7 เลเยอร์ / อินพุต และ ดับภาพ (ต้องล็อกอินขั้นสูง)

1. ส่วน **เลเยอร์และอินพุต** เลือกอินพุตให้เลเยอร์หนึ่ง → **นำไปใช้** (`W0506`) ดูว่าเลเยอร์นั้นเปลี่ยนแหล่งภาพ
2. **ดับภาพ (FTB)** ของหน้าจอหนึ่ง → ดูว่าหน้าจอนั้นดับแบบค่อย ๆ ลด → **ยกเลิกดับภาพ** (`W0409`: type 0 = ดับ, 1 = ยกเลิก)

**คาดว่า:** เฉพาะเลเยอร์/หน้าจอที่เลือกเปลี่ยน สถานะในตารางหน้าจอเปลี่ยนตาม

**จดถ้าต่าง:** สลับอินพุตไม่ได้ (เครื่องปฏิเสธ? ข้อความ error), สลับได้แต่ผิดแหล่ง, อินพุตที่เป็น **crop** ใช้ไม่ได้ (โปรแกรมส่ง `sourceType: 1, streamId: 0, templateId: 0` ตามที่โมดูลอ้างอิงทำ — แหล่ง IPC/NDI ยังไม่รองรับ), ดับภาพแล้วสถานะในตารางกลับด้าน

### 15.8 บันทึกความสว่างลงการ์ดรับ (ถาวร — ทำเป็นขั้นสุดท้าย)

1. ตั้งความสว่างเป็นค่าที่ต้องการให้คงอยู่ (หรือค่าเดิมของเครื่อง) ที่เมนู **ความสว่าง**
2. เมนู **H series** → **บันทึกความสว่าง** ของหน้าจอหนึ่ง (`W0417` เขียนลงการ์ดรับ)
3. ปิด-เปิดไฟ H5 (หรือการ์ดรับ) แล้วอ่านความสว่างใหม่

**คาดว่า:** ค่าคงอยู่หลังเปิดไฟใหม่ **จดถ้าต่าง:** ค่ากลับเป็นค่าเดิม, ไฟกระพริบ/ผิดปกติตอนบันทึก **อย่าบันทึกซ้ำหลายครั้งติดกัน** (เขียนแฟลช)

### 15.9 เครือข่ายไม่เสถียร (UDP)

UDP ไม่มีการรับประกันการส่งถึง โปรแกรมส่งซ้ำอัตโนมัติสูงสุด 2 ครั้งเมื่อเครื่องเงียบ (รวม 3 ครั้ง รอครั้งละ 2 วินาที ≈ 6 วินาทีก่อนขึ้น error) ลองดู:
1. ดึงสาย LAN ของ H5 ออกแล้วกดปุ่ม **รีเฟรช** → ต้องขึ้น **ตัวควบคุมไม่ตอบสนองภายในเวลาที่กำหนด** (ไม่ค้างตลอดไป)
2. เสียบกลับ กด **รีเฟรช** อีกครั้ง → ต้องอ่านได้โดยไม่ต้องเชื่อมต่อใหม่

**จดถ้าต่าง:** ค้าง/ไม่ฟื้นหลังเสียบสาย, ต้องตัดการเชื่อมต่อแล้วต่อใหม่ถึงจะกลับมา, ใช้เวลานานเท่าไรกว่าจะขึ้น error

## 16. Taurus (TU15 Pro / TU20 Pro / TB40 / TB50 / TB60) ผ่าน LAN (และ USB ถ้าเป็น network adapter)

ส่วนนี้สำหรับเจ้าของ **Taurus** (เครื่องเล่นมัลติมีเดีย) เป็นอุปกรณ์คนละตระกูลกับ MCTRL/VX และ H series: โปรแกรมคุยกับ Taurus ด้วย **โปรโตคอลจัดการของ Taurus** ผ่าน **TCP 16606** (เข้ารหัส TLS เมื่อเครื่องเปิด Privacy mode) และค้นหาเครื่องด้วย **UDP 16601** ไม่ใช่โปรโตคอลทะเบียน TCP 5200 ของ MCTRL

**เหตุผลที่ต้องทดสอบ:** โปรโตคอลจัดการของ Taurus ไม่มีเอกสารสาธารณะ โค้ดฝั่ง Taurus ใช้ไลบรารีโอเพนซอร์ส `@novastar/taurus` 0.4.1 (MIT) ซึ่งผู้เขียนระบุเองว่าได้จากการทำ reverse engineering และไม่มีหลักฐานว่าทดสอบครบทั้ง 5 รุ่น ของเราทดสอบกับตัวจำลองที่ใช้ตัวเข้ารหัส/ถอดรหัสแพ็กเก็ตของไลบรารีเดียวกันเท่านั้น (ถูกต้องตามรูปแบบแพ็กเก็ตของไลบรารี แต่ **ไม่ได้พิสูจน์ว่าเครื่องจริงตอบแบบเดียวกัน**)

ทำตามหัวข้อ 0 (ความปลอดภัย) เหมือนเดิม **ทำทีละขั้น หยุดทันทีที่เจออะไรผิดปกติ** ใช้ Taurus ที่ไม่ได้ขึ้นจอใช้งานจริงของลูกค้า ทดสอบรุ่นไหนให้จดรุ่นและเฟิร์มแวร์ (จากเมนู/ViPlex) ไว้ทุกครั้ง

**รหัสผ่าน:** โปรแกรมไม่มีรหัสผ่านเริ่มต้นของ Taurus และไม่เก็บรหัสผ่านไว้ (ใช้ครั้งเดียวตอนเชื่อมต่อ ตัดการเชื่อมต่อแล้วต้องกรอกใหม่) ใช้รหัสผ่านเดียวกับที่ใช้ล็อกอินเครื่องใน ViPlex (ชื่อผู้ใช้เริ่มต้นของไลบรารีคือ `admin` ถ้าเครื่องใช้ชื่ออื่นให้กรอกในช่อง **ชื่อผู้ใช้**) ห้ามใส่รหัสผ่านในรายงานผล

### 16.1 เตรียมการเชื่อมต่อ

**ทาง LAN (ทดสอบก่อน):**
1. ต่อ Taurus เข้าเครือข่ายเดียวกับคอมพิวเตอร์ (ซับเน็ตเดียวกัน) แล้วดู **IP ของ Taurus** จาก ViPlex หรือเมนูของเครื่อง (**จด IP**)
2. รอบแรกให้ปิด ViPlex / VNNOX Care / โปรแกรมอื่นที่ล็อกอินเครื่องอยู่ก่อน (Taurus อาจจำกัดจำนวนผู้ล็อกอินพร้อมกัน — ภายหลัง **จดว่า** เปิด ViPlex ค้างไว้ได้ไหมโดยโปรแกรมนี้ยังเชื่อมต่อได้)
3. Windows Firewall ถามสิทธิ์ครั้งแรก เลือก **อนุญาต** (ต้องรับ UDP ตอบกลับจากพอร์ต 16601 ได้) ถ้าไม่พบเครื่อง ลองปิด firewall ชั่วคราวเพื่อแยกสาเหตุ แล้ว **จดว่าเป็นสาเหตุหรือไม่**

**ทาง USB (ถ้ามี USB Type-B ที่เครื่อง):**
1. ต่อสาย USB แล้วเปิด Windows **Device Manager** → ดูใน **Network adapters** ว่ามี adapter ใหม่ (เช่น "Remote NDIS based Internet Sharing Device") โผล่ขึ้นมาไหม และใน **Ports (COM & LPT)** มี COM ใหม่ไหม (**จดว่าโผล่เป็นอะไร** หรือไม่โผล่เลย)
2. ถ้าเป็น network adapter: ดู IP ที่ adapter ได้ (`ipconfig`) แล้วลองพิมพ์ IP ของ Taurus ที่อยู่ซับเน็ตเดียวกับ adapter นั้นในช่อง **โฮสต์เครือข่าย** (README ของไลบรารีระบุว่า FTP ของ Taurus ใช้ได้ "over LAN or USB RNDIS" แต่ **ไม่ยืนยัน** ว่าพอร์ต 16606 ผ่านทางนี้ได้)
3. ถ้าเป็น COM: โปรแกรมนี้ไม่มีทางเชื่อม Taurus ผ่าน COM ด้วยโปรโตคอลจัดการ ให้ลองตามหัวข้อ 2 (เชื่อมต่อ USB แบบ MCTRL) แล้ว **จดว่าตอบหรือไม่** (ยังไม่รู้ว่า Taurus พูดโปรโตคอลทะเบียนผ่าน USB หรือไม่)

### 16.2 ค้นหาและเชื่อมต่อ (ทดสอบรหัสผ่านผิดและถูก)

1. เมนู **การเชื่อมต่อ** → กด **ค้นหา** โดยไม่กรอกโฮสต์ (ค้นหาแบบ broadcast ด้วยไลบรารี) **จดว่าพบ Taurus หรือไม่** แล้วลองอีกครั้งโดยพิมพ์ IP ในช่อง **โฮสต์เครือข่าย** — ผลสองแบบอาจต่างกัน (broadcast ข้ามซับเน็ต/VLAN ไม่ได้) **จดไว้**
2. หาแถวประเภท **Taurus (LAN)** ชื่อเช่น `TB60 192.168.1.60 (SN …)` → **จดรุ่นและ SN ที่แสดง** เทียบกับป้ายเครื่อง
3. กด **เชื่อมต่อ** → ต้องขึ้นกล่อง **เชื่อมต่อ Taurus** ขอรหัสผ่าน (ยังไม่มีการเชื่อมต่อจนกว่าจะกดปุ่มในกล่อง)
4. ใส่รหัสผ่าน **ผิด** → กด **เชื่อมต่อ** → **คาดว่า** ขึ้นข้อความแดง "เครื่องเล่นปฏิเสธการเข้าสู่ระบบ" กล่องไม่ปิด แถบบนยังเป็น "ยังไม่ได้เชื่อมต่อ" **จด:** เครื่องปฏิเสธเร็วแค่ไหน, ปฏิเสธซ้ำหลายครั้งแล้วเครื่องล็อกบัญชีชั่วคราวไหม (อย่าลองผิดเกิน 3 ครั้ง)
5. ใส่รหัสผ่าน **ถูก** → **คาดว่า** แถบบนเป็น **เชื่อมต่อแล้ว: TB60** (หรือรุ่นของคุณ) กล่อง **ตัวควบคุมที่เชื่อมต่ออยู่** แสดงรุ่น เฟิร์มแวร์ `unknown` (ไลบรารีไม่มีฟิลด์เฟิร์มแวร์ของตัวเครื่อง) **พอร์ตเอาต์พุต** และตาราง **การ์ดรับ** (รุ่นการ์ดแสดงเป็น `Unknown (0x…)` รหัสรุ่นดิบ + เวอร์ชัน FPGA/MCU) — **จดจำนวนพอร์ต/การ์ดเทียบกับจริง**
6. เมนูด้านซ้ายต้องเหลือ: **การเชื่อมต่อ, ความสว่าง, ทดสอบและการแสดงผล, Taurus** (เมนู MCTRL และ H series ต้องหายไป)
7. กด **ตัดการเชื่อมต่อ** แล้วกด **เชื่อมต่อ** ใหม่ → ต้องถามรหัสผ่านอีกครั้ง (รหัสไม่ถูกเก็บ)

**จดถ้าต่าง:** ไม่พบเครื่อง (จด IP/พอร์ต/ข้อความ error), พบแต่รุ่นว่าง, **รหัสผ่านถูกแต่ถูกปฏิเสธ** (อาจเป็นเฟิร์มแวร์ที่ไม่รับตัวระบุแพลตฟอร์ม `platformVersion 3.6.0` ที่ไลบรารีใช้ — จดเวอร์ชันเฟิร์มแวร์), เครื่องที่เปิด **Privacy mode** (TLS) เชื่อมต่อไม่ได้, เชื่อมต่อได้แต่ค้าง, รหัสผิดแล้วข้อความต่างจากที่คาด (แยกว่าเครื่องตอบ `logined:false` หรือสถานะ error)

### 16.3 อ่านค่า (ไม่ต้องล็อกอินขั้นสูง)

เมนู **Taurus** (ระหว่างนี้ปุ่มที่เป็นการเขียนถูกล็อกอยู่ถ้ายังไม่ล็อกอินขั้นสูง):
1. กล่อง **เครื่องเล่น:** รุ่น, SN, ที่อยู่, พอร์ตจัดการ, Privacy mode เทียบกับค่าจริงใน ViPlex
2. **เซนเซอร์แสงรอบข้าง:** ถ้ามีเซนเซอร์ ให้ใช้มือบังแล้วกด **รีเฟรช** ดูว่าค่าเปลี่ยน → **จดค่าตอนสว่าง/ตอนบัง และหน่วยที่เดาได้** ถ้าไม่มีเซนเซอร์ ต้องขึ้น "เครื่องนี้ไม่มีเซนเซอร์แสง"
3. **การตั้งค่าจอ LED (อ่านอย่างเดียว):** ขนาด (พิกเซล), คอลัมน์ x แถว, จำนวนการ์ดรับ เทียบกับที่ตั้งไว้ใน ViPlex/NovaLCT
4. **แหล่งเล่นภาพ:** โหมดปัจจุบัน เทียบกับค่าใน ViPlex (ซิงโครนัส/อะซิงโครนัส)
5. **แหล่งวิดีโอ:** รายการแหล่ง (Internal/HDMI), สัญญาณ HDMI มี/ไม่มี (ลองถอดสาย HDMI แล้วกด **รีเฟรช**), ความละเอียดที่อินพุต HDMI แจ้ง

**จดถ้าต่าง:** ค่าไหนไม่ตรง, อ่านไม่ได้ (error อะไร), จำนวนพอร์ต/การ์ดที่คำนวณจากผังจอไม่ตรงกับจริง

### 16.4 ความสว่าง (เขียนชั่วคราว ไม่ต้องล็อกอินขั้นสูง เหมือน MCTRL)

1. ยังไม่ต้องล็อกอินขั้นสูงของโปรแกรม (การ **บันทึก** ความสว่างถาวรเท่านั้นที่ต้องล็อกอิน) เมนู **ความสว่าง** ต้องเห็นเฉพาะแถบ **ความสว่างรวม** (Taurus ไม่มีเกน RGB) และค่าที่อ่านจากเครื่อง
2. เทียบค่าที่โปรแกรมอ่านกับค่าความสว่างใน ViPlex ณ ตอนนั้น (**จดสองค่า**)
3. ตั้ง 20% → **นำไปใช้** → ดูจอสว่างลดลงจริง และค่าอ่านกลับต้องเป็น 20% → ตั้ง 100% → กลับมาสว่าง
4. ปิด-เปิดไฟ Taurus → อ่านความสว่างใหม่

**คาดว่า:** ค่าเปลี่ยนตามที่ตั้ง และ **กลับเป็นค่าเดิมหลังปิด-เปิดไฟ** (เขียนแบบไม่บันทึกลงแฟลช — ไลบรารีส่ง `solidity:false`) **จดถ้าต่าง:** ค่าที่ตั้งกับค่าใน ViPlex ไม่ตรงกัน (เช่น ตั้ง 20 แต่ ViPlex แสดง 8 → สเกลไม่ใช่ 0–100 เท่ากัน), อ่านกลับเป็นค่าอื่น, ค่าคงอยู่หลังปิด-เปิดไฟ (แปลว่าเขียนลงแฟลชโดยไม่ตั้งใจ)

### 16.5 บันทึกความสว่างลงเครื่อง (ถาวร — ทำท้าย ๆ)

1. ตั้งความสว่างที่ต้องการให้คงอยู่ที่เมนู **ความสว่าง** (หรือค่าเดิมของเครื่อง)
2. เมนู **Taurus** → **บันทึกความสว่างลงเครื่องเล่น** (ไลบรารีส่ง `solidity:true`)
3. ปิด-เปิดไฟ Taurus แล้วอ่านความสว่างใหม่

**คาดว่า:** ค่าคงอยู่ **จดถ้าต่าง:** ค่ากลับเป็นค่าเดิม, จอกระพริบ/ผิดปกติตอนบันทึก **อย่าบันทึกซ้ำถี่ ๆ** (แฟลชมีอายุเขียน)

### 16.6 แหล่งเล่นภาพ ซิงโครนัส / อะซิงโครนัส (ต้องล็อกอินขั้นสูง ผลเห็นบนจอทันที)

เตรียมแหล่ง HDMI ที่มีภาพต่อเข้า Taurus และมีคอนเทนต์ในเครื่อง:
1. เมนู **Taurus** → **ใช้ HDMI (ซิงโครนัส)** → จอต้องแสดงภาพจาก HDMI และ **โหมดปัจจุบัน** เปลี่ยนเป็นซิงโครนัส
2. **ใช้เครื่องเล่นภายใน (อะซิงโครนัส)** → จอกลับไปเล่นคอนเทนต์ในเครื่อง
3. **ใช้ HDMI และสลับไปภายในเมื่อสัญญาณหาย** → ถอดสาย HDMI → จอควรสลับไปเล่นในเครื่อง; เสียบกลับ → ควรกลับมา HDMI (**จดผลจริง**)
4. ตรวจใน ViPlex ว่าการตั้งค่าตรงกัน (โหมดแหล่งวิดีโอ)

**จดถ้าต่าง:** สลับไม่ได้ (เครื่องปฏิเสธ? ข้อความ error), สลับได้แต่ ViPlex แสดงโหมดไม่ตรง, ค่า scaling/offset ที่ตั้งไว้เดิมเปลี่ยนไป (ไลบรารีควรคงค่าเดิมไว้ — อ่านก่อนเขียน), หลังสลับ **โหมดปัจจุบัน** แสดง "อื่น ๆ" ทั้งที่คาดว่าเป็นซิงโครนัส/อะซิงโครนัส (แปลว่าตารางแปลงโหมดของเราไม่ตรงกับเครื่อง)

### 16.7 ภาพทดสอบ และ จอดำ / หยุดภาพ — ต้อง "ไม่รองรับ"

1. เมนู **ทดสอบและการแสดงผล** ต้องมีข้อความ **Taurus ไม่รองรับภาพทดสอบและโหมดการแสดงผล…** และ **ปุ่มทุกปุ่มกดไม่ได้**
2. (ไลบรารี `@novastar/taurus` ไม่มีคำสั่งเหล่านี้ จึงไม่มีการส่งอะไรไปเครื่อง) ถ้าเจอวิธีสั่งภาพทดสอบ/จอดำผ่าน ViPlex ให้ **จดชื่อเมนูใน ViPlex** ไว้ เผื่อพัฒนาต่อ

### 16.8 ลองใช้เมนู MCTRL เดิม (อ่านอย่างเดียว) ชี้ไปที่ Taurus ผ่าน TCP 5200

**ที่มา:** Taurus เปิดพอร์ต TCP 5200 ด้วย (โค้ดปรับเทียบค่าสีของไลบรารีเปิดการเชื่อมต่อ 5200 ไปที่ Taurus เพื่ออ่าน/เขียนรีจิสเตอร์ของ **การ์ดรับ** โดยตรง) แต่ **ยังไม่ทราบ** ว่าคำสั่งฝั่ง **การ์ดส่ง** (ที่เมนูการ์ดส่ง/การเชื่อมต่อใช้) Taurus ตอบหรือไม่ โปรแกรมไม่มีโค้ดเฉพาะสำหรับเส้นทางนี้ — ขั้นนี้เป็นการทดลองเพื่อดูว่าตอบอะไร **ห้ามกดปุ่มเขียน/บันทึกใด ๆ ในขั้นนี้**

1. กด **ตัดการเชื่อมต่อ** Taurus (โปรแกรมเชื่อมต่อได้ทีละเครื่อง)
2. เมนู **การเชื่อมต่อ** → พิมพ์ IP ของ Taurus ในช่อง **โฮสต์เครือข่าย** (ไม่ต้องระบุพอร์ต ค่าเริ่มต้น 5200) → **ค้นหา**
3. ดูตาราง: ถ้า Taurus ตอบคำสั่งอ่านรุ่นการ์ดส่ง (`ReadControllerModelId`) บน 5200 จะมีแถวประเภท **เครือข่าย (LAN)** `IP:5200` โผล่ **เพิ่ม** จากแถว Taurus (LAN) — **จดว่าโผล่หรือไม่** ถ้าไม่โผล่ แปลว่าเครื่องไม่ตอบคำสั่งชุดการ์ดส่งบน 5200 (หรือพอร์ตถูกปิด)
4. ถ้าโผล่ → **เชื่อมต่อ** แถว `IP:5200` → จด **รุ่น** (จะเป็น `Unknown (0x....)` = รหัสรุ่นดิบ นำมาเทียบกับ `modelId` จากผลค้นหา Taurus), **เฟิร์มแวร์**, **พอร์ตเอาต์พุต**, **การ์ดรับ**
5. เปิดทีละเมนู (อ่านอย่างเดียว) แล้วจดว่าแต่ละหน้า **ตอบ / error / หมดเวลา:** **การ์ดส่ง** (อ่านค่า), **การ์ดรับ** (อ่านการ์ดรับ ฝั่งอ่านเท่านั้น), **ผังการเชื่อมต่อจอ** (อ่านจากฮาร์ดแวร์), **ตรวจสอบสถานะ** (monitoring) — เทียบค่าที่ได้กับหน้า Taurus (จำนวนการ์ดรับ, ผังจอ)
6. ห้ามกด: เขียนค่าการ์ดรับ, บันทึกลงฮาร์ดแวร์, เขียนผังจอ (หัวข้อ 11–13) บนเส้นทางนี้ จนกว่าเจ้าของจะประเมินผลอ่านแล้วตัดสินใจเอง — การเขียนรีจิสเตอร์การ์ดรับตรง ๆ โดยข้ามระบบจัดการของ Taurus อาจทำให้ค่าในเครื่องไม่ตรงกับที่ ViPlex เก็บไว้

**ผลที่มีประโยชน์ที่สุด:** รายการเมนูที่ตอบสำเร็จ กับที่ไม่ตอบ (ตารางท้ายหัวข้อ) เพราะจะบอกว่าควรต่อยอดฟีเจอร์การ์ดรับ/ผังจอ/ตรวจสอบสถานะของ Taurus ผ่าน 5200 ได้หรือไม่

### 16.9 เครือข่ายไม่เสถียร / เครื่องรีบูต

1. ขณะเชื่อมต่ออยู่ ดึงสาย LAN ของ Taurus แล้วกด **รีเฟรช** ที่เมนู Taurus → ต้องขึ้น error (ไม่ค้างตลอดไป — แต่ละคำขอหมดเวลาเอง) **จดเวลาที่ใช้**
2. เสียบสายกลับ กด **รีเฟรช** อีกครั้ง → **คาดว่า** อ่านได้เลย หรือขึ้น "ยังไม่ได้เชื่อมต่อตัวควบคุม" (ถ้าเครื่องตัดการเชื่อมต่อ TCP) → ให้ตัดการเชื่อมต่อแล้วเชื่อมต่อใหม่พร้อมรหัสผ่าน **จดว่าเกิดแบบไหน**
3. สั่งรีบูต Taurus (จาก ViPlex) ระหว่างเชื่อมต่อ → โปรแกรมต้องรายงานว่าไม่ได้เชื่อมต่อ (ไม่ค้าง) แล้วต่อใหม่ได้หลังเครื่องบูตเสร็จ
4. เปิดทิ้งไว้ 10–30 นาทีโดยไม่กดอะไร แล้วกด **รีเฟรช** → **จดว่า session ยังอยู่หรือหลุด** (โปรแกรมไม่มี keep-alive เอง)

## 17. ส่งไฟล์ค่าฮาร์ดแวร์ขั้นสูงกลับ (ทำเป็นขั้นสุดท้าย)

ทำหลังทดสอบครบทุกขั้นที่เกี่ยวข้อง (หรือทุกครั้งที่เปลี่ยนค่าในเมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง**) เพื่อให้ผู้พัฒนาได้ค่าที่ "ใช้ได้จริง" ไปแก้ค่าเริ่มต้นในโค้ด

1. เมนู **ตั้งค่าฮาร์ดแวร์ขั้นสูง** → ตรวจว่าค่าที่แสดงในช่อง **ค่าปัจจุบัน** คือค่าที่ทำให้จอดำ / หยุดภาพ / บันทึก / ผังจอทำงานถูกต้องตามที่ทดสอบ (ค่าที่ต่างจากค่าเริ่มต้นจะมีป้าย **ต่างจากค่าเริ่มต้น**)
2. ช่อง **หมายเหตุถึงผู้พัฒนา** พิมพ์สั้น ๆ เช่น รุ่นตัวควบคุม / ขั้นไหนผ่านด้วยค่าอะไร / ขั้นไหนยังไม่ผ่าน
3. กด **ส่งออกเป็นไฟล์** จะได้ไฟล์ `rockzalct-hardware-overrides-<วันที่>-<เวลา>.json` (ส่งออกได้โดยไม่ต้องล็อกอินขั้นสูง)
4. ส่งไฟล์นี้กลับมาพร้อมตารางผลในขั้น 14 (ผู้พัฒนาเปิดไฟล์เดียวกันนี้ด้วยปุ่ม **นำเข้าจากไฟล์…** ได้)
5. ค่าที่แก้ไว้จะถูกเก็บในเครื่องและใช้ต่อเมื่อเปิดโปรแกรมใหม่ (เฉพาะโหมดเชื่อมต่อเครื่องจริง) ถ้าต้องการกลับเป็นค่าเดิมกด **คืนค่าเริ่มต้น…**

หมายเหตุ: ค่าในกลุ่ม **การปรับเทียบ** (`eraseSpiFlash`, `correctionEnabledBit`, `correctionBrightnessTypeBit`) ยังไม่มีขั้นทดสอบในเอกสารนี้ **อย่าแก้ค่าเหล่านี้ถ้าผู้พัฒนาไม่ได้ขอ**

## 18. ตั้งค่าอัจฉริยะ (Smart Settings) — เขียนค่าการ์ดรับทีละใบ ลงแค่ RAM

เมนู **ตั้งค่าอัจฉริยะ (Smart Settings)** เป็นตัวช่วยทีละขั้นสำหรับโมดูลที่ **ไม่ซับซ้อน** (ตารางพิกเซล/จุดไม่ได้ทำเอง): เก็บค่าเดิม → ตั้งค่าพื้นฐานโมดูล → หาลำดับสี RGB → หาขั้ว OE → ตรวจและเลือกว่าจะเก็บ/คืน/บันทึกถาวร

> **ทำหลังขั้น 11 ผ่านแล้วเท่านั้น** บน **จอเล็ก/ชุดทดสอบ** ใช้ **การ์ดรับเพียงใบเดียว** ล็อกอินขั้นสูงแล้ว (แถบบนขึ้น **ระดับ: ขั้นสูง**) และมีไฟล์สำรองจากหัวข้อ 0 ข้อ 3 แล้ว
> ทุกการเขียนในหัวข้อนี้ลงเฉพาะ RAM ของการ์ด (ปิด-เปิดไฟแล้วหาย) **ยกเว้นขั้น 18.7 ที่ตั้งใจบันทึกลงแฟลช** ห้ามทำ 18.7 บนจอที่ใช้งานจริง
> โมดูลที่ซับซ้อน/ไม่สม่ำเสมอ ยังต้องใช้ไฟล์ตั้งค่าโมดูลจาก NovaLCT (ตัวช่วยนี้ไม่เขียนตารางพิกเซล/จุดและลำดับสแกน)

**ค่าที่ยังไม่ยืนยันกับเครื่องจริง (UNVERIFIED):** ผลของค่า **ทิศทางข้อมูล** (0 แนวนอน / 1 แนวตั้ง), ผลของ **ขั้ว OE** (0 เปิดเมื่อสูง / 1 เปิดเมื่อต่ำ) กับภาพที่เห็น, และ **ความหมายของฟิลด์รหัส RGB** (ใช้การแมปแบบปกติก่อน มีปุ่มลองแบบกลับด้านถ้ายังผิด) รายการรีจิสเตอร์ที่เขียน: ทิศทางข้อมูล `0x02000009`, ความกว้าง `0x0200000A`, ความสูง `0x0200000B`, ไอซีไดรเวอร์ `0x0200000C`, สแกน `0x0200000D`, ขั้ว OE `0x0200000E`, ตัวถอดรหัส `0x0200000F`, กลุ่มข้อมูล `0x0200001B`, รหัส RGB `0x0200005C`

### 18.1 สแนปช็อต (จุดคืนค่า)

1. เมนู **ตั้งค่าอัจฉริยะ (Smart Settings)** ขั้น **1. สแนปช็อต** เลือกการ์ดทดสอบ 1 ใบ → **อ่านสแนปช็อต**
2. ต้องเห็น **เก็บสแนปช็อตของพอร์ต N / การ์ด M แล้ว** และตารางค่า 9 รายการ **จดทุกค่าลงตารางด้านล่าง** (ความกว้าง/ความสูง/สแกน/กลุ่มข้อมูล/ไอซี/ตัวถอดรหัส/ทิศทาง/รหัส RGB/ขั้ว OE) แล้วเทียบกับค่าใน NovaLCT ของจอเดียวกัน
3. ก่อนอ่านสำเร็จ ขั้น 2–5 และปุ่ม **คืนค่าตามสแนปช็อต** ต้องกดไม่ได้ (ลองถอดสายแล้วกดอ่าน ต้องขึ้น error และขั้นอื่นยังกดไม่ได้)

**จดถ้าต่าง:** ค่าที่อ่านต่างจาก NovaLCT, อ่านไม่สำเร็จ (ระบุข้อความ error), ค่าไอซี/ตัวถอดรหัสที่แสดงเป็น "รหัส N" (ไม่มีชื่อ)

### 18.2 ค่าพื้นฐานโมดูล

1. ขั้น **2. ค่าพื้นฐานโมดูล** เปลี่ยน **ความกว้างโมดูล** เพียงค่าเดียว (เช่น +8 พิกเซล) กด **นำค่าพื้นฐานไปใช้ (RAM เท่านั้น)** → หน้าต่างต้องแสดงการ์ดและค่าเดิม → ใหม่ → กด **ใช่ ดำเนินการต่อ**
2. ดูจอว่าภาพเปลี่ยนเฉพาะบริเวณของการ์ดนี้ แล้วไปขั้น 1 ดูว่าแถบ **ค่าในการ์ดต่างจากสแนปช็อต** ขึ้น และ (ขั้น 1) ช่องเลือกการ์ดถูกล็อก
3. กด **คืนค่าตามสแนปช็อต** → ยืนยัน → ภาพกลับเหมือนเดิม
4. ทดลองใส่ค่านอกช่วง (ความกว้าง 0 หรือ 256, สแกน 129) ต้องกดนำไปใช้ไม่ได้
5. (ถ้ามีโปรไฟล์ในไลบรารีโมดูล) เลือกจาก **เติมค่าจากไลบรารีโมดูล** → **ใช้** → ค่าในช่องต้องเปลี่ยนตามโปรไฟล์ แต่ยังไม่เขียนลงการ์ดจนกว่าจะกดนำไปใช้

**จดถ้าต่าง:** อ่านกลับ (ขั้น 1 อ่านซ้ำหลังคืนค่า) ไม่ตรงกับที่เขียน, ภาพเพี้ยน/ดับ, **ทิศทางข้อมูล** เปลี่ยนแล้วภาพกลับหัว/สลับอย่างไร (ระบุ 0 หรือ 1 และสิ่งที่เห็น — ค่านี้ยังไม่ยืนยัน)

### 18.3 ลำดับสี RGB

1. ขั้น **3. ลำดับสี RGB** กด **แสดงสีแดง** → จอ **ทั้งหมด** ต้องขึ้นสีแดง (สีทดสอบขึ้นทุกการ์ด) ดูที่โมดูลของการ์ดทดสอบแล้วเลือกคำตอบ **แสดงสีแดง: เห็นเป็น…** ทำเช่นเดียวกับเขียวและน้ำเงิน
2. ถ้าสีถูกอยู่แล้ว ต้องขึ้น **สีถูกต้องอยู่แล้ว ไม่ต้องเขียน** ถ้าสลับ ต้องขึ้น **รหัส RGB ใหม่** → กด **เขียนลำดับสี RGB (RAM เท่านั้น)** → ยืนยัน
3. แสดงแดง/เขียว/น้ำเงินอีกครั้งเพื่อตรวจ ต้องตรงกับสีที่สั่งแล้ว
4. ถ้ายังผิด (เกิดเฉพาะกรณีสีหมุนวนทั้งสามสี) กด **ลองการแมปแบบกลับด้าน** แล้วตรวจอีกครั้ง
5. กด **หยุดภาพทดสอบ** เมื่อเสร็จ

**จดถ้าต่าง:** คำตอบที่เลือกทั้ง 3 ข้อ, รหัสที่โปรแกรมคำนวณ, ผลหลังเขียนครั้งที่ 1 และหลัง "แบบกลับด้าน" (ถูก/ผิด) — ใช้ตัดสินว่าการแมปแบบปกติหรือกลับด้านถูกต้อง, สีไม่ตรงทั้งที่ทั้งสองแบบ (แจ้งรหัส RGB ที่อ่านได้ใน 18.1 และหลังเขียน)

### 18.4 ขั้ว OE

1. ขั้น **4. ขั้ว OE** กด **แสดงสีขาว** ดูโมดูล แล้วเลือก **ปกติ (ขาวสว่าง)** หรือ **มืด หรือกลับสี**
2. ถ้าเลือก **ปกติ** ต้องไม่มีปุ่มเขียน ถ้าเลือก **มืด หรือกลับสี** ต้องขึ้น **สลับขั้ว OE จาก … เป็น …** → กด **เขียนขั้ว OE (RAM เท่านั้น)** → ยืนยัน → ดูว่าภาพดีขึ้นหรือไม่
3. ถ้ายังมืด ตอบใหม่ จะสลับกลับค่าเดิม **คืนค่าตามสแนปช็อต** ถ้าภาพเสีย

**จดถ้าต่าง:** ค่า OE ก่อน/หลัง และอาการที่เห็นก่อน/หลัง (ใช้ยืนยันว่า 0 = เปิดเมื่อสูง, 1 = เปิดเมื่อต่ำ ตรงกับภาพอย่างไร), ภาพมืด/กะพริบ/ดับหลังสลับ

### 18.5 เสร็จสิ้น — เปรียบเทียบและเลือกทาง

1. ขั้น **5. เสร็จสิ้น** ตารางต้องแสดงเฉพาะค่าที่ต่างจากสแนปช็อต (ถ้าไม่ต่างต้องขึ้น **ไม่ต่างจากสแนปช็อต**)
2. กด **เก็บไว้ (RAM เท่านั้น)** → ต้องไม่มีการเขียนเพิ่ม ปิด-เปิดไฟแล้วค่าต้องกลับเป็นค่าสแนปช็อต
3. ตั้งค่าใหม่อีกรอบ แล้วกด **คืนค่าตามสแนปช็อต** → ยืนยัน → อ่านสแนปช็อตซ้ำ ทุกค่าต้องเท่ากับที่จดใน 18.1

### 18.6 บันทึกเป็นโปรไฟล์โมดูล

ในขั้น 5 ใส่ชื่อ → **บันทึกลงไลบรารีโมดูล** → เมนู **การ์ดรับ** ต้องเห็นโปรไฟล์ใหม่ (ขนาด สแกน กลุ่มข้อมูล ไอซี ตรงกับที่ตั้ง; ตัวถอดรหัส/ทิศทาง/OE/RGB ไม่ถูกเก็บในโปรไฟล์ — เป็นไปตามที่ออกแบบ)

### 18.7 บันทึกลงแฟลชของการ์ด (ถาวร) — ทำเมื่อ 18.2–18.5 ผ่านและยอมให้การ์ดทดสอบเปลี่ยนถาวร

1. ในขั้น 5 กด **บันทึกลงแฟลชของการ์ด…** → ต้องขึ้นหน้าต่าง **บันทึกลงฮาร์ดแวร์?** ที่ระบุพอร์ต/การ์ดที่ถูกต้อง (ยกเลิกแล้วต้องไม่มีการเขียน) → ยืนยัน → ต้องเห็น **บันทึกการ์ดรับแล้ว 1 ใบ**
2. ปิดไฟตัวควบคุม+จอ รอ 10 วินาที เปิดใหม่ เชื่อมต่อใหม่ → อ่านสแนปช็อตใหม่ ต้องได้ค่าที่บันทึก (ค่าคำสั่งบันทึกยังไม่ยืนยัน ดูหัวข้อ 12)
3. คืนค่าเดิม แล้วบันทึกซ้ำให้การ์ดกลับสู่สภาพเดิม
4. ถ้าการเขียนล้มเหลวกลางทาง (เช่น ถอดสายระหว่างกดนำไปใช้) ต้องขึ้นกรอบแดงบอกว่าเขียนอะไรไปแล้ว/อะไรล้มเหลว และปุ่มบันทึกลงแฟลชต้องกดไม่ได้จนกว่าจะคืนค่า
