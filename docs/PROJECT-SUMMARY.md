# สรุปโปรเจกต์ RockzaLCT (ถึง v0.1.3)

โปรแกรมตั้งค่าและควบคุมจอ LED เทียบเท่า NovaStar NovaLCT เขียนใหม่ทั้งหมด (Electron + React + TypeScript)
Repo: `RockZa27/RockzaLCT` · branch งาน `claude/rockzalct-plan`
Release: https://github.com/RockZa27/RockzaLCT/releases/tag/v0.1.0 (pre-release, ไฟล์ `RockzaLCT-Setup-0.1.0.exe`)
v0.1.1: เพิ่มหน้า Smart Settings (ยังไม่ได้ทดสอบกับจอจริง — ดูคู่มือข้อ 18)
v0.1.2: นำเข้าไฟล์ .rcfgx / .scr ของ NovaLCT (ยังไม่ได้ทดสอบกับเครื่องจริง — ดูคู่มือข้อ 19)
v0.1.3: ค่าจาก NovaLCT (จอดำ/หยุดภาพ/บันทึก/ลำดับ X-Y), ชื่อรุ่นการ์ดรับ, ขั้นตำแหน่งพิกเซลใน Smart Settings, หน่วยจริง °C/V/%RH/rpm/gamma (ยังไม่ได้ทดสอบกับเครื่องจริง)

- **สร้างตารางพิกเซล/จุดโดยไม่ให้ผู้ใช้มาร์ก** — NovaLCT เองก็ไม่คำนวณ: ตารางจุดมาจากการที่ผู้ใช้คลิกตำแหน่ง LED ที่สว่างทีละจุด ตอนนี้ทำแบบเดียวกันได้ในขั้น "แมปพิกเซล" (ดูหัวข้อด้านล่าง) สำหรับชิปรุ่นที่ 3 · **ยังไม่ทำ:** ตารางรันไลน์ของชิปรุ่นที่ 4 (`IsCabinetToolChip`, `0x04000000`), ไทมิ่ง/OE/แกมมา/ค่าไดรเวอร์ของชิป (ไม่มีข้อมูลชิป — ต้องใช้ไฟล์ `.rcfgx` จาก NovaLCT), ตู้ไม่สม่ำเสมอ, ไดรเวอร์แบบอนุกรม, การ์ดส่งแบบอะซิงโครนัส (Taurus) · โมดูลซับซ้อนทำได้โดยนำเข้าไฟล์ `.rcfgx` ที่ export จาก NovaLCT (หน้า "นำเข้าไฟล์ NovaLCT")
- seam/bright-dark line fix, ปรับคาลิเบรตเฉพาะพื้นที่

## แมปพิกเซล (Smart Settings ขั้นที่ 6) — ยังไม่ได้ทดสอบกับเครื่องจริง (คู่มือข้อ 18.8)

- **ทำอะไร:** ผู้ใช้กรอกขนาดโมดูล สแกน กลุ่มข้อมูล ทิศทางข้อมูล (จำนวนโมดูล/จุดต่อไดรเวอร์ถ้ามี) → โปรแกรมให้การ์ดทำให้ตำแหน่งในตารางสว่างทีละจุด (n = K·M·c + M·b + a วาดเป็นพิกเซลเดียวบนจอคอมที่ป้อนการ์ดส่ง) → ผู้ใช้คลิกช่องที่ LED สว่าง (เมาส์/คีย์บอร์ด ย้อนคลิก ล้างทั้งหมด สร้างอัตโนมัติ จุดไม่ใช้) → ตัวอย่างก่อนส่ง → ส่ง ตารางจุด (`0x03000000`, X/Y ต่อรายการ, ≤ 832 รายการ) ลำดับสแกน (`0x1C000100`) จำนวนจุด (`0x0200001D`) และรีจิสเตอร์รูปทรงที่ไม่ขึ้นกับชิป (แถวต่อกลุ่ม `0x02000047` ตำแหน่งเริ่ม `0x02000083` ลำดับกลุ่ม `0x02000011` ขนาดควบคุม จำนวนกลุ่มจริง/ตรรกะ โหมดสแกน ฯลฯ) แล้วสั่งการ์ดสร้างตารางรันไลน์เอง (`0x01000013` สองครั้งห่าง 100 มิลลิวินาที)
- **ไม่แตะไทมิ่งชิป:** รีเฟรช/GCLK/ตาราง OE/แกมมา/ค่าไดรเวอร์คงที่การ์ดถืออยู่ ("เฉพาะรูปทรง") ชิปซับซ้อนอาจยังต้องใช้ `.rcfgx`
- **ความปลอดภัย:** ต้องล็อกอินขั้นสูง · RAM เท่านั้น ไม่มีการบันทึกแฟลชโดยอัตโนมัติ · อ่านสแนปช็อตจากการ์ดก่อนเขียน (อ่านไม่ได้ = ไม่แตะอะไร) · ยกเลิก/ย้อนกลับ = ปิดโหมดสมาร์ท (การ์ดส่ง `0x02000040` การ์ดรับ `0x02000104`) + โหลดจากแฟลช `0x01000010` + ล้างหยุดภาพ/จอดำ/ล็อก · ล้มเหลวกลางทางหยุดทันทีและรายงานสิ่งที่เขียนแล้ว · broadcast ต้องติ๊กยืนยัน (NovaLCT ส่ง broadcast) · ระหว่างทำ ตัวควบคุมถูกล็อก (ใช้ `withExclusiveSession` แบบ lease คงอยู่ข้ามหลายคำสั่ง) และออกจากหน้ากลางทางจะย้อนกลับให้
- **แก้ข้อผิดพลาดในสเปก:** ที่อยู่ลำดับสแกนในสเปกเขียน `0x1C000000` แต่เลขฐานสิบ `469762304` และไลบรารี (`AddressMapping.Module_ScanSequenceInfoAddr`) คือ `0x1C000100` โปรแกรมใช้ตัวหลัง (เทสตรวจกับไลบรารี)
- **ยังไม่ยืนยัน:** สูตรจำนวนโมดูล/ทิศทางต่อโมดูลจากสเปก (ไฟล์ `.rcfgx` ของผู้ใช้ 2x5 โมดูลมี ShiftUnit/PointNumPerDrive/จำนวนกลุ่มทางกายภาพไม่ตรงสูตร จึงเปิดช่องให้ใส่ "จุดต่อไดรเวอร์" เอง) · ไม่เขียนตารางตำแหน่ง/ขนาดพอร์ตของการ์ดส่งที่ NovaLCT เขียนก่อนเริ่ม (โปรแกรมเลื่อน DVI offset เป็น 0,0 แล้วคืนค่า) · เขียน `AddrExtend = 5` ตามสเปกทุกครั้ง · วาดพิกเซลที่มุมซ้ายบนของจอที่เลือกด้วยหน้าต่างไร้ขอบ (ตั้ง scaling 100%) · ค่าแถวที่ไม่ได้ใช้ของตารางกลุ่ม (กลุ่ม ≥ จำนวนจริง) เป็นไปตามค่าเริ่มต้นของสเปกและตัดเหลือ 1 ไบต์

## นำเข้าไฟล์ NovaLCT (.rcfgx / .scr) — ยังไม่ได้ทดสอบกับเครื่องจริง (คู่มือข้อ 19)

- **.rcfgx**: zip ที่มี XML (`ScanBoardProperty`) + ก้อนไบนารี `RCCB` = รายการเขียนรีจิสเตอร์ (แอดเดรส ข้อมูล เวลารอ การโพลล์) หน้านี้ถอดไฟล์ในโปรเซสหลัก แสดงสรุป (รุ่นการ์ด เวอร์ชัน NovaLCT โมดูล/ตู้ ชิป สแกน กลุ่มข้อมูล รีเฟรช/เกรย์/แกมมา ตารางแอดเดรส) แล้วส่งให้การ์ดเดียวหรือ broadcast ตามลำดับและเวลารอของไฟล์ หยุดที่ระเบียนแรกที่ล้มเหลวและรายงานจำนวนที่เขียนแล้ว ทดสอบกับไฟล์จริง 2 ไฟล์ (NovaLCT 5.3.0 รุ่น MRV328 และ 5.9.2 รุ่น NV7516 ที่มีก้อน 512 KiB) และกับ simulator ด้วยโค้ดโคเดกจริง
- **ความปลอดภัย:** ต้องล็อกอินขั้นสูง ตรวจทุกระเบียนก่อนส่ง (แอดเดรสต้องอยู่ในช่วงที่เคยเห็นจากไฟล์จริง นอกช่วงปฏิเสธทั้งไฟล์) ต้องยืนยันรุ่นการ์ด (โปรแกรมอ่านรุ่นการ์ดรับจริงไม่ได้ จึงให้ผู้ใช้ยืนยันเอง) ระหว่างส่งล็อกคำสั่งอื่นของตัวควบคุมนั้น ไม่บันทึกลงแฟลชอัตโนมัติ (ต่อด้วยขั้นตอนบันทึกเดิม)
- **ยังไม่ยืนยัน:** ไฟล์มีระเบียนคำสั่ง `0x01......` (`0x0100009D` FlashCabinet, `0x01000012` Recalculate ฯลฯ) ที่ส่งตามลำดับเดิม ไม่ยืนยันว่าทำให้การ์ดจำค่าถาวรเองหรือไม่ จึงไม่รับประกันว่า "ปิด-เปิดไฟแล้วย้อนกลับ" (คู่มือข้อ 19.6) · broadcast ช้า (หยุด 50 มิลลิวินาทีต่อแพ็กเก็ต ไฟล์ 512 KiB ≈ 1 นาที 45 วินาที) · ใช้ปลายทางแบบเดียวกับฟีเจอร์อื่น (ตัวส่ง 0, พอร์ต 0xFF, การ์ด 0xFFFF)
- **.scr**: ถอดด้วย `@novastar/screen` (MIT, ตรวจ CRC) แสดงจอ/การ์ด/ตำแหน่ง แปลงเป็นผังของเราเมื่อเป็นจอมาตรฐานเดียวที่เรียงเป็นตาราง แล้วโหลดเข้าหน้าผังการเชื่อมต่อจอ (เขียนลงเครื่องยังผ่านการตรวจ+ยืนยันเดิมของหน้านั้น) จอซับซ้อน/ไม่สม่ำเสมอแสดงอย่างเดียว
- `@novastar/screen@2.5.2` เป็นไลบรารี MIT ของผู้อื่น ใช้เป็นดีเพนเดนซีสำหรับ `.scr` เท่านั้น (ตัวโหลด `.rcfgx` ไม่ถูก export จึงเขียนตัวถอด RCCB เองโดยอ้างอิงโครงสร้างจากไลบรารีนั้น) โหลดแบบ lazy (ครั้งแรก ~0.6 วินาที) และ smoke test ตรวจการถอดไฟล์ `.scr` ในแอปที่ package แล้ว

## ค่าจาก NovaLCT ที่ยังต้องยืนยันกับเครื่องจริง (แก้ได้จากหน้าตั้งค่าฮาร์ดแวร์ขั้นสูง)

ค่าเหล่านี้เปลี่ยนจาก "เดา" เป็นค่าที่ NovaLCT เขียนจริง (อ่านจากโค้ด NovaLCT) แต่ยังไม่เคยทดสอบกับเครื่องจริง:

- byte จอดำ/หยุดภาพ (`DISPLAY_MODE_VALUES`): เปิด = 255, ปิด = 0 ทั้งสองรีจิสเตอร์ (0x02000100 / 0x02000102)
- คำสั่งบันทึกลง flash (`SAVE_COMMAND_VALUES`): การ์ดส่ง 0x01000001 และการ์ดรับ 0x01000011 เขียนค่า 0
- ลำดับ X/Y ของตำแหน่งการ์ดรับในผังจอ: byte = X ต่ำ, X สูง, Y ต่ำ, Y สูง (`x-low`) — ลองกับจอเล็กก่อน
- ค่าลบ flash คาลิเบรต (0x01000008 เขียน 0) และบิตสวิตช์คาลิเบรต (บิต 0 = เปิด, บิต 1 = ชนิดความสว่าง) ตรงกับ NovaLCT — อย่าเปลี่ยนเองก่อนคุยกัน
- Smart Settings: ทิศทางข้อมูล (0 แนวนอน / 1 แนวตั้ง) และขั้ว OE (0 high-enable / 1 low-enable) ตรงกับ NovaLCT; ฟิลด์รหัส RGB อนุมานจากการออกแบบวิซาร์ดของ NovaLCT (ฟิลด์ = ช่องเอาต์พุต, ค่า = ช่องข้อมูลต้นทาง แบบ `inverse` ลองก่อน ยังมีปุ่มลองแบบตรงข้าม) ความมั่นใจปานกลาง-สูง ยังไม่ยืนยันกับเครื่องจริง — ดูหัวข้อ 18 ของคู่มือทดสอบ

ผู้ที่เคยบันทึกไฟล์ `hardware-overrides.json` ไว้ จะได้ค่าที่บันทึกไว้ต่อไป (ไม่ถูกย้ายค่าอัตโนมัติ)
- หน่วยของ refresh rate / อุณหภูมิและความชื้นของการ์ดส่ง (0x02000002) / grayscale (ยังแสดงเป็นค่าดิบ), ชื่อรุ่นการ์ด (ขึ้น "Unknown (0x....)")
- **เสร็จแล้ว (แสดงหน่วยจริง จากสูตรที่ถอดจาก NovaLCT ในบันทึกโปรโตคอล Q7 — ยังรอเทียบกับเครื่องจริง):** อุณหภูมิ °C (ค่า x 0.5, บิต 0 = ติดลบ, บิต 7 = ใช้ได้), ความชื้น %RH, แรงดันไฟเลี้ยงการ์ดรับ V (x 0.1), พัดลม rpm (x 50), ควัน, แกมมา (28 = 2.8, 0xFE = ตารางกำหนดเอง) ทั้งหน้าตรวจสอบสถานะและหน้าการ์ดรับ พร้อมค่าดิบแสดงข้างกัน · เกณฑ์แจ้งเตือนเป็น °C/V (ค่าเริ่มต้น 60/70 °C, 4.5–5.5 V) และย้ายค่าเกณฑ์เดิมที่เก็บเป็นค่าดิบให้อัตโนมัติ · การเขียนแกมมายังเป็นค่าไบต์ดิบ (มีตัวเข้ารหัส `encodeGamma` พร้อมเทสต์แต่ยังไม่ต่อกับช่องแก้ไข)
- Taurus ผ่านพอร์ต 5200 ใช้หน้าของ MCTRL ได้แค่ไหน (คู่มือข้อ 16.8)

## ความปลอดภัยที่บังคับไว้

- คำสั่งที่เปลี่ยนการแสดงผล/บันทึกถาวร ต้องล็อกอินขั้นสูง (รหัสเริ่มต้น `admin`) + หน้าต่างยืนยัน · ปรับความสว่างชั่วคราวไม่ต้องล็อกอินทุกรุ่น
- ลบ/บันทึก flash คาลิเบรต ต้องสำรองค่าของการ์ดใบนั้นครบ 2 MiB ก่อน + พิมพ์ตำแหน่งการ์ด + ทีละใบ
- ปุ่ม Apply ปิดจนกว่าจะอ่านค่าจากการ์ดสำเร็จ · พอร์ต > 254 ถูกปฏิเสธก่อนส่ง · คำสั่ง H5 ที่ไม่ idempotent ไม่ส่งซ้ำ

## คุณภาพและการตรวจสอบ

- เทส 938 ตัว (simulator 19, device 545, desktop 374; ข้ามไว้ 1) + typecheck + build ใน CI ทุก push
- Smoke test เปิดโปรแกรมที่ package แล้วจริง ทั้ง Linux (CI) และ Windows (ก่อนออก release) — ยืนยัน `SMOKE OK discovered=3` (ตอนนี้ต่อท้าย `scr=15` = ถอดไฟล์ .scr ตัวอย่างในแอปที่ package แล้ว)
- ตรวจโค้ดทั้งโปรเจกต์ 1 รอบ: พบ 20 บั๊ก ยืนยันจริงทุกข้อ แก้ครบพร้อมเทสที่ล้มก่อนแก้
- คะแนน agent ทุกตัวอยู่ใน `docs/agent-scorecard.md` (Sonnet 22 ตัว ทิ้ง 1 ตัว ส่งกลับแก้ 3 ตัว)

## วิธีออกเวอร์ชันใหม่

1. แก้ `version` ใน `apps/desktop/package.json` (เช่น 0.1.1)
2. push เข้า `main` → workflow รันเทส + smoke บน Windows → สร้าง **draft release** ให้เอง
