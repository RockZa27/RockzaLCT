# Agent scorecard

งานแต่ละชิ้นทำโดย subagent (Sonnet) แล้ว Opus ตรวจซ้ำเองทุกข้อ คะแนนเต็ม 10

| เกณฑ์ | คะแนน | วิธีวัด |
|---|---|---|
| Build + typecheck ผ่าน | 2 | รันซ้ำเองจาก root |
| Tests ผ่าน | 2 | รันซ้ำเอง |
| คุณภาพเทส | 2 | ทดสอบพฤติกรรมจริง ไม่ใช่ mock ตัวเอง / ครอบคลุม error path |
| ทำตามสเปก / ไม่แตะนอกขอบเขต | 2 | ตรวจ diff เทียบ prompt |
| ความซื่อตรงของรายงาน | 2 | สิ่งที่อ้างว่าทำได้ ต้องพิสูจน์ได้จริง |

**ต่ำกว่า 6 = ทิ้งงานทั้งหมด** แล้วสร้าง agent ตัวใหม่ด้วย prompt ที่แก้จุดอ่อนของรอบก่อน
**6–7 = ส่งกลับให้แก้** เฉพาะจุด
**8 ขึ้นไป = merge**

## ผลรอบที่ 5 (ตัวติดตั้ง + CI + คู่มือทดสอบ)

| งาน | Agent | คะแนน | ผล |
|---|---|---|---|
| ตัวติดตั้ง Windows, CI, คู่มือทดสอบ | sonnet #10 | **9/10** | merge — แก้ปัญหา pnpm symlink กับ electron-builder ด้วย `pnpm deploy`, คู่มือทดสอบภาษาไทยเรียงจากปลอดภัยไปเสี่ยงและเริ่มด้วยการสำรองค่า (−1: เปิด `npmRebuild` ทั้งที่มี N-API prebuild แล้ว — Opus ปิด) |

**บั๊กร้ายแรงที่ Opus เจอหลังรวมงาน (ไม่มีเทสตัวไหนจับได้):** Opus เปิดแอปที่ package แล้วจริงใต้ Xvfb พบว่า **แอปพังตั้งแต่เปิด** — `@novastar/serial` เรียก `require()` แพ็กเกจ `conf` ที่เป็น ESM-only แต่ Electron 33 ใช้ Node 20 ที่ทำไม่ได้ (เทส end-to-end ก่อนหน้าผ่านเพราะรันบน Node 22) → อัปเกรดเป็น Electron 37 (Node 22.16) และเพิ่ม `--smoke-test` + ขั้น CI ที่ package แล้วบูตแอปจริง; ยืนยันแล้วว่าขั้นนี้ **ล้ม** บน Electron 33 และ **ผ่าน** บน 37
